# Instrument на RelaxDev — отдельная миграционная ветка

## Что уже готово
- Python 3.12 + FastAPI + **прямой PostgreSQL**, без SQLite.
- Dockerfile слушает `0.0.0.0:${PORT:-8080}`; встроенный режим RelaxDev: **Docker**.
- При `RELAXDEV_DEPLOY=1` приложение **не стартует**, если не установлены `DATABASE_URL` и `APP_PASSWORD`. Логин по умолчанию `admin`.
- `/healthz` проверяет соединение с PostgreSQL; наружу отдаёт лишь `{"ok":true}`.
- Автозагрузка IMAP на RelaxDev **отключена** даже при заданном `MAIL_HOST`, пока не выставлено `MAIL_IMPORT_ENABLED=1`. До восстановления старой БД этот флаг **не включать**.
- Старая ВМ и ветка main **не затронуты**.

## Пошаговый перенос
1. Создать проект `instrument` из `HR-analyze/instrument`, ветка **`relax-migration`**, способ сборки **Docker** (именно Dockerfile, не Node.js).
2. Создать **отдельную новую PostgreSQL** для Instrument в RelaxDev.
3. Установить переменные:
   - `DATABASE_URL` — выданная RelaxDev строка подключения к новой PostgreSQL (секрет; никому не отправлять).
   - `APP_USER=admin`
   - `APP_PASSWORD` — новый надёжный пароль (секрет).
   - `PORT=8080` и `WEB_PORT=8080`, **если панель требует**. Dockerfile по умолчанию использует 8080.
   - `MAIL_IMPORT_ENABLED=0` (не запускать второе чтение почты).
4. **Не** задавать `POSTGRES_PASSWORD` из старого Docker Compose: он нужен только старому локальному контейнеру БД.
5. Запустить deploy, дождаться `/healthz → {"ok":true}`. Открыть системный адрес RelaxDev; браузер попросит логин и пароль.
6. Сделать небольшую **тестовую** загрузку XLSX, убедиться, что данные остались после redeploy.
7. Пока не переключать корпоративный домен и не выдавать адрес сотрудникам.

## ВАЖНО — старые данные и почта
Новая база изначально пустая. После возвращения старой VM потребуется `pg_dump` старой Instrument DB и **проверенный перенос/сверка**, а не прямое восстановление поверх уже используемой новой БД. Загружаемые на новой площадке файлы нельзя затирать. Не запускать два IMAP-поллера на разных БД: письма помечаются прочитанными, и часть истории может попасть лишь в одну базу.

### Проверки
GitHub Actions `.github/workflows/relax-check.yml` прогоняет pytest с отдельной тестовой PostgreSQL, сборку Docker и smoke-test HTTP Basic Auth и /healthz.

### Диагностика
- `/healthz` 500 или приложение не стартует: убедиться в `DATABASE_URL` и правах пользователя PostgreSQL.
- HTTP 401 для основной страницы — ожидаемо до входа с `APP_USER` и `APP_PASSWORD`.
- Не публиковать скриншоты строки подключения, паролей и секретов.
